# Pattern: Photo-header + text-panel card (гибридная карточка)

## Назначение

Дать карточке одновременно сильное фото и много легибельного текста (тег-лайн, многострочное
описание, нумерованный список шагов, цена, CTA), не жертвуя ни фото, ни читаемостью. Полный
оверлей-текст поверх фото (градиент + текст внизу) ломается, как только текста становится больше
2–3 коротких строк — либо градиент съедает бо́льшую часть фото, либо текст в светлых зонах фото
нечитаем.

## Когда использовать

- Карточка прайса/программы/тарифа, где нужны и фото, и полный набор данных: заголовок, короткий
  тег-лайн, описание на 2+ строки, список шагов/фич, цена/длительность, CTA.
- Клиент/бриф просит «добавить фото» к существующему текстовому блоку, но сам текстовый блок
  сокращать нельзя (цена и состав должны остаться полностью читаемы).

## Когда не использовать

- Контента на карточке мало (заголовок + одна короткая строка) — обычный оверлей (фото + градиент +
  текст поверх) проще и не требует лишней панели. См. карточки направлений/специалистов в том же
  проекте, где именно оверлей уместен.
- Карточка кликабельна как единое целое и фото несёт смысловую, а не декоративную роль (например,
  превью видео) — там разделение на две зоны может выглядеть избыточным.

## Структура

- Карточка — `flex flex-col`, две зоны друг под другом:
  1. **Фото-шапка** — фиксированный `aspect-ratio` (не full-bleed на всю карточку), `relative
     overflow-hidden`, `<img>` внутри `absolute inset-0 object-cover`. На само фото ложится **только**
     короткий контент: числовой индекс, категория-badge, длительность — то, что не боится любого
     фона фото. Лёгкий градиент (`rgba(...,0) → rgba(...,0.5-0.6)` снизу) только чтобы бейджи не
     терялись, не для текста абзацами.
  2. **Текстовая панель** — сплошной фон карточки (не поверх фото), весь основной контент: заголовок,
     тег-лайн, описание, список, цена, CTA. Обычные `text-*` классы без градиентов/теней — легибельность
     не зависит от того, что на фото.
- Соотношение сторон фото-шапки короче, чем у full-bleed-оверлей-карточек того же проекта (например
  `4:3`/`4:5` вместо `4:5`/полной высоты) — фото здесь «заголовок», а не всё содержимое карточки.
- Для сеток с большим числом карточек (6-8+) держи CTA внутри панели компактным (текстовая
  ссылка-стрелка), а не полноразмерной pill-кнопкой — иначе сетка визуально шумит от повторяющихся
  одинаковых кнопок; полноразмерную кнопку оставляй для одного акцентного CTA на всю секцию.

## Реализация (пример)

```astro
<article class="flex flex-col overflow-hidden rounded-xl border border-graphite bg-carbon">
  <div class="relative aspect-[4/3] overflow-hidden">
    <img src={item.img} alt={item.alt} loading="lazy" decoding="async"
      class="absolute inset-0 h-full w-full object-cover" />
    <div class="absolute inset-0"
      style="background: linear-gradient(180deg, rgba(20,16,12,0) 55%, rgba(20,16,12,0.55) 100%);" />
    <div class="absolute inset-x-0 bottom-0 flex items-center justify-between p-5">
      <span class="ghost-index">{item.num}</span>
      <span class="badge">{item.duration}</span>
    </div>
  </div>

  <div class="flex flex-1 flex-col p-7">
    <h3 class="font-display text-3xl">{item.title}</h3>
    <p class="mt-1 text-sm text-accent">{item.tagline}</p>
    <p class="mt-4 leading-relaxed">{item.desc}</p>
    <ul class="mt-7 space-y-3 border-t pt-6">
      {item.steps.map((s, i) => <li>{i + 1}. {s}</li>)}
    </ul>
    <div class="mt-8 flex items-center justify-between border-t pt-6">
      <span class="font-display text-xl">{item.priceFrom}</span>
      <a href="#booking" class="text-sm">Записаться →</a>
    </div>
  </div>
</article>
```

## Production-паттерны

- Фото-шапка и текстовая панель — общий `border`/`rounded-xl` на внешнем `<article>`, не на каждой
  зоне отдельно, иначе виден шов между ними.
- До реальных фото карточку можно собирать с плейсхолдер-путями к `public/`: сборка (Astro/Vite) не
  падает на несуществующей статической ссылке — верстается и проверяется layout, фото подставляются
  последним шагом.
- Если в сетке 6+ карточек, ограничивай длину `desc`, чтобы панели не расходились по высоте сильнее
  чем на 1-2 строки — иначе сетка выглядит рвано.

## Частые ошибки

- Пытаться впихнуть список шагов/цену/CTA поверх фото с одним общим градиентом — при длинном тексте
  либо градиент занимает 70%+ фото, либо часть текста ложится на светлый участок и нечитаема.
- Разный `aspect-ratio` фото-шапки в одной сетке карточек — визуально рвёт ритм грида.
- Полноразмерная `.pill`-кнопка на каждой карточке в сетке 6-8+ штук — сетка выглядит шумно; для такой
  плотности достаточно компактной текстовой ссылки-стрелки.

## Альтернативы

- Full-bleed оверлей (фото на всю карточку + градиент + текст поверх) — для карточек с малым
  количеством текста (заголовок + одна строка), см. карточки направлений/команды в том же проекте.
- Текст слева / фото справа в одной строке (не друг над другом) — работает на широких карточках
  (1-2 в ряд), но ломается в плотных сетках 3-4+ колонок на десктопе.
