# Pattern: Screen-section lead landing

## Назначение

Собрать lead-generation лендинг так, чтобы каждый смысловой блок выглядел как отдельный управляемый экран, а длинные блоки не растягивали страницу случайными хвостами. Паттерн особенно полезен для B2B лендингов с каталогом, калькулятором, FAQ и плавающим CTA/квизом.

## Когда использовать

- Лендинг продает услугу с длинным выбором: техника, тарифы, предложения, FAQ.
- Визуальная задача: "один блок на один экран", но каталог/FAQ/калькулятор могут быть выше viewport.
- Есть fixed header, плавающий CTA или квиз, который может перекрывать формы.

## Когда не использовать

- Контент должен читаться как длинная статья без экранных остановок.
- На mobile важнее естественная вертикальная прокрутка, чем жесткая высота секций.
- Блок содержит таблицы или формы, где внутренняя прокрутка ухудшит доступность.

## Структура

- Общая секция получает `min-height: calc(100svh - var(--header-height))`.
- Короткие секции центрируются по вертикали и имеют ограниченные vertical paddings.
- Длинные секции получают bounded viewport: `height` или `max-height` + внутренний `overflow-y-auto`.
- Fixed header компенсируется через `scroll-margin-top: var(--header-height)` на якорных секциях.
- Плавающий CTA/квиз проверяется отдельно: он не должен перекрывать кнопку формы, CTA калькулятора или последний чекбокс.

## Реализация (пример)

```tsx
<Section
  id="calculator"
  marker="03 / Калькулятор"
  title="Калькулятор предварительного платежа"
  contentClassName="lg:h-[calc(100svh-var(--header-height))] lg:justify-start"
>
  <LeasingCalculator />
</Section>
```

```css
:root {
  --header-height: 88px;
}

.screen-inner {
  min-height: calc(100svh - var(--header-height));
}

section[id] {
  scroll-margin-top: var(--header-height);
}
```

## Production-паттерны

- Проверять не только скриншотом, но и DOM-метриками: `getBoundingClientRect`, `scrollHeight`, `clientHeight`, видимость последнего интерактивного элемента.
- Для каталога делать разные layouts: общий режим может быть плотной витриной, выбранная категория должна растягивать 1-2 карточки без пустого grid-фона.
- Квиз-воронка должна синхронизироваться с основным расчетом/формой, а не быть отдельным тупиком.
- Все финансовые расчеты помечать как предварительные и не как публичную оферту.

## Частые ошибки

- Растянуть весь каталог на высоту всех карточек: секция становится длинной и ломает правило одного экрана.
- Оставить `bg-*` на grid-контейнере: при 2 карточках в широкой сетке появляется пустая серая зона.
- Полагаться на `scrollIntoView` при fixed header без `scroll-margin-top`: блок открывается под шапкой или не там, где ожидает пользователь.
- Валидировать "поместилось" только визуально: скриншот не ловит нижний чекбокс, скрытый за плавающей кнопкой.
- Делать FAQ раскрытием, которое растягивает всю страницу, вместо внутренней scroll-зоны.

## Альтернативы

- Обычный длинный landing flow без экранных ограничений: лучше для editorial-контента.
- Tabs/accordion вместо внутренних scroll-зон: подходит, если блок можно честно разбить на короткие состояния.
- Отдельные страницы каталога/FAQ: лучше для SEO-многостраничников.
