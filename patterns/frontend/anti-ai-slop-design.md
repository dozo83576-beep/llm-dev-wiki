# Anti-AI-slop design

Используй этот паттерн, когда нужно понять, как не сделать скучный AI-slop лендинг: до кода фиксируются референсы, визуальное направление, конверсионная структура и запреты на дефолтные AI-приёмы.

## Назначение

Паттерн убирает «AI-слоп» — статистически средний вид, который модель выдаёт по умолчанию: кремовый фон, serif-дисплей, hero + три карточки в ряд, эмодзи вместо иконок, ноль деталей. Такой вид читается как дёшево с первого взгляда. Паттерн перебивает дефолт через явные спеки, проработанные микро-детали и не дефолтный layout.

Главный принцип: качество = решения ДО генерации. «Сделай красиво» даёт слоп. Конкретное направление + точные значения дают агентский уровень.

## Когда использовать

- Лендинг, продающая страница, сайт под клиента / продукт / эксперта.
- Пользователь жалуется, что дизайн «шаблонный / как нейросеть / дешёвый» и хочет «премиум / как у агентств».
- Даже запрос «просто сделай красивый сайт» без деталей — здесь риск слопа максимальный.

## Когда не использовать

- Внутренний инструмент / админка, где скорость и плотность данных важнее визуального вау. Там работает [Design-systems](../../docs/02-frontend/Design-systems.md) с плотными dashboard-токенами.
- Строгий бренд-гайд клиента уже задаёт визуал — следуй ему, а не общим анти-слоп приёмам.

## Production-паттерны

### 1. Перебить дефолтный house style модели

У модели стойкий дефолт, который лезет сам: тёплый кремовый фон (~`#F4F1EA`), serif-дисплей (Georgia / Fraunces / Playfair), италик-акценты, терракотовый цвет. Общие фразы («не используй кремовый», «сделай чисто») его не убирают — модель переключается на другой такой же дефолт.

Перебивается двумя способами вместе:

- **Конкретика.** Не «тёмный с акцентом», а точные значения: `фон #0A0A0B, акцент #FF2E7E, заголовки Saira Extra Condensed`. Точные спеки выполняются точно.
- **Выбор направления ДО кода.** Зафиксируй артефакт по [design-direction-brief](../../prompts/design-direction-brief.md): 3–4 варианта, каждый одной строкой `фон hex / акцент hex / шрифт`. Пользователь выбирает один — строится только он.

### 2. Микро-детали (их «чувствуют»)

- Линейные иконки [Lucide](https://lucide.dev), НЕ эмодзи. Эмодзи мгновенно удешевляют.
- БЕЗ длинного и среднего тире в копии (`—`, `–`) — только дефис (`-`).
- mono-метки и индексы секций: `[001]`, `FIG.02`, `CASE/01`, `© 2026`.
- hairline-линии (1px тонкие границы), угловые маркеры на карточках.
- гигантские outline / ghost-числа на фоне секций.
- лёгкая grain-текстура поверх плоских заливок.

### 3. Анимации, но со вкусом

counter-up на цифрах, reveal-stagger (элементы по очереди), hover-lift, spotlight за курсором в hero, marquee, вращающиеся badge-кружки. Анимация оправдывает себя функцией и частотой показа, а не «это красиво»; держи motion-бюджет и уважай `prefers-reduced-motion`. Полные правила (длительности < 300ms, `ease-out`, только `transform`/`opacity`) — в [Motion](../../docs/02-frontend/Motion.md) и [Pattern: Purposeful motion](purposeful-motion.md).

### 4. Не дефолтный layout

Никаких «hero + 3 карточки в ряд». Асимметрия, наложения, нестандартная сетка, воздух. Один точный акцент, продуманные радиусы, тени, hover-состояния. Если блок выглядит «как у всех» — переделать.

Для лендинга держи конверсионную дисциплину: один экран = одна мысль, H1 до 7 слов, proof/trust до первого сомнения, CTA без лишнего выбора. Красивый визуал не компенсирует непонятный оффер.

### 5. Цвет текста по поверхностям

Не один глобальный `--text`. Используй токены по поверхности, иначе светлый текст наследуется на светлую секцию. Полное правило — в [semantic-theme-text-tokens](semantic-theme-text-tokens.md).

### 6. Анти-повторяемость (не сходиться к одному шаблону)

Модель сходится к одной и той же связке от генерации к генерации (один hero, один шрифт, один layout). Чтобы перебить это, **выбор делается явно ДО кода**, а не «как выйдет»:

- Зафиксируй оси вариативности и выбери по одному значению на проект: hero-архитектура (split / центрированный / asymmetric / типографический / с медиа сбоку), типографический стек (например, grotesque + serif vs condensed-дисплей + гротеск-боди vs моно-акцент), плотность сетки и ритм отступов, характер motion.
- Не переиспользуй ту же связку, что в прошлом проекте/секции — сверься с уже сделанным (`case-studies/`) и выбери другую ось.
- «Дёшево vs дорого»: дорого читается через тугую типографику (плотный tracking у крупных заголовков), осмысленный спейсинг и проработанные состояния; дёшево — равномерная серость, дефолтные радиусы, центрированный текст везде.

Это дисциплина выбора, а не рандом ради рандома: каждый вариант всё равно проходит остальные правила паттерна.

### 7. Расширенный стоп-лист «AI-вида»

Конкретные паттерны, которые мгновенно выдают генерацию — не использовать:

- Карточки в карточках (cards-in-cards), вложенные бордеры/тени без смысла.
- Квадрат-плитка с иконкой над каждым заголовком секции (icon-tile above every heading).
- Серый текст на цветном/тёмном фоне (gray-on-color) — проваленный контраст и «дешёвый» вид.
- «Inter для всего» (или Roboto/Arial/system) как единственный шрифт без дисплей-пары.
- Purple→blue (фиолетово-синий) градиент на белом — самый узнаваемый дефолт модели.
- Эмодзи как иконки фич/кнопок; центрированный текст во всех секциях подряд.

### 8. Outlier-анализ до дизайна

Перед продающим сайтом посмотри не только лучшие референсы, но и плохие сайты ниши. Из сильных бери принципы доверия, ритм секций и CTA. Из слабых выпиши, что нельзя повторять: перегруз текста, generic стоки, фейковые отзывы, отсутствие proof, одинаковые карточки и CTA без контекста.

## Частые ошибки

- Оставить дефолтный кремовый / serif, потому что «и так нормально».
- Эмодзи в фичах и кнопках вместо линейных иконок.
- Длинное тире в заголовках и копии.
- Layout «hero + 3 карточки» как единственная структура.
- Шрифт-дисплей, который не поддерживает кириллицу, — текст сыпется в tofu (см. [cyrillic-self-host-fonts](cyrillic-self-host-fonts.md)).
- Выдуманные кейсы, цифры и отзывы. Доверие — главный актив страницы; нет данных — ставь явные плейсхолдеры `[ отзыв со скрина — клиент даст ]`, не фантазию.

## Security / performance risks

- Тяжёлые decorative-анимации и particle-фоны бьют по LCP/INP. Контролируй вес и количество анимируемых элементов (см. [Performance](../../docs/02-frontend/Performance.md)).
- grain / большие SVG-числа держи лёгкими (CSS / inline SVG), не тащи мегабайтные PNG.
- Сторонние компонент-библиотеки добавляют JS — для статичного лендинга переноси приёмы вручную (см. [Premium-components](../../docs/02-frontend/Premium-components.md)).

## Testing strategy

- Визуальный smoke: нет эмодзи, нет длинного/среднего тире, нет дефолтного кремового/serif, нет layout «hero + 3 карточки».
- Есть микро-детали (mono-метки, hairline, ghost-числа) и хотя бы пара анимаций.
- Контраст по computed-цветам (не только CSS-правилам) на тёмных и светлых секциях.
- Шрифт грузится, кириллица не в tofu, есть системный фолбэк.
- Lighthouse a11y ≥ 95; анимации отключаются при `prefers-reduced-motion`.

## Edge cases

- Кириллица в condensed-дисплеях: многие латиница-онли — проверяй заранее.
- Тёмные media-карточки внутри светлой секции — явно возвращай `--text-on-dark`.
- Региональная аудитория (СНГ): Google Fonts CDN может не прогрузиться — self-host обязателен.
