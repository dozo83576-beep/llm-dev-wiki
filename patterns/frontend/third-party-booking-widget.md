# Pattern: Third-party booking widget (попап записи)

## Назначение

Встроить онлайн-запись (или похожий сторонний виджет) попапом прямо на странице, без перехода на сайт
провайдера: посетитель выбирает время на нашем сайте, аккаунт нужен только владельцу. Паттерн заодно
фиксирует обязательную деградацию и требование региональной доступности провайдера.

## Когда использовать

- Лендинг/контентный сайт, где нужна self-service запись (консультация, услуга, демо).
- Достаточно стороннего сервиса записи (DIKIDI, и т.п.), своя CRM не нужна.
- Аудитория в регионе, где домен провайдера доступен (см. «Частые ошибки»).

## Когда не использовать

- Провайдер недоступен в регионе аудитории (напр. Calendly в РФ) — выбери локально доступный сервис,
  см. [урок про региональную доступность](../../lessons-learned/2026-06-13-region-accessible-third-party-embeds.md).
- Нужны серверная логика бронирования, оплата, своя БД слотов — это уже backend, не виджет.

## Структура

- **Загрузчик провайдера подключается один раз на странице** (`<script>` с виджет-лоадером). Он сам
  находит на странице элементы-триггеры и навешивает попап.
- **Кнопка-триггер** — обычная ссылка с условным href, который понимает лоадер (напр. DIKIDI:
  `https://dikidi.ru/#widget=<ID>`). Кнопок на странице может быть **несколько** (разные услуги/виджеты) —
  лоадер один.
- **Graceful fallback**: без скрипта (не загрузился/выключен JS) клик по ссылке открывает запись на
  сайте провайдера — ничего не теряется. Рядом — запасной канал (Telegram/телефон).
- **Конфиг централизован**: ссылки/скрипт/цены вынесены в одно место (напр. `consts.ts`), плейсхолдеры
  помечены для владельца.
- **Секретов нет**: это публичный клиентский виджет; токены/ключи тут не нужны.

## Реализация (пример, Astro/DIKIDI)

```astro
---
// consts.ts: BOOKING.widgetScript, BOOKING.free.url (#widget=...), BOOKING.paid.url ...
import { BOOKING } from "../consts";
---
<!-- Кнопка-триггер: без target, чтобы открывался попап; href — запасной переход -->
<a href={BOOKING.free.url} class="cta">Записаться</a>
<!-- ... может быть вторая кнопка с другим #widget=<ID> ... -->

<!-- Лоадер ОДИН раз на странице; is:inline, чтобы Astro не бандлил внешний скрипт -->
<script is:inline src={BOOKING.widgetScript}></script>
```

## Production-паттерны

- Лоадер строго один на страницу (иначе двойная инициализация/двойные обработчики).
- Проверяй, что HTML действительно содержит и скрипт, и ссылку `#widget=<ID>` (бандлер мог вырезать —
  спасает `is:inline`).
- Держи запасной канал связи всегда видимым: виджет может не подняться (сеть, регион, сбой провайдера).
- В превью без интернета сам попап не откроется — верифицируй DOM-метриками
  (см. [headless-preview-verification](../../lessons-learned/2026-06-11-headless-preview-verification.md)).

## Частые ошибки

- Выбрать провайдера, недоступного в регионе аудитории (Calendly в РФ) — фича мертва у посетителей.
- Подключить лоадер несколько раз (по разу в каждом компоненте-кнопке).
- Поставить `target="_blank"` там, где лоадер ожидает перехват клика, и сломать попап.
- Не оставить fallback — при сбое виджета запись становится недоступной.

## Альтернативы

- [Telegram lead notification](../backend/telegram-lead-notification.md) — если нужен не календарь со
  слотами, а простая заявка «перезвоните»; работает в любом регионе.
- Своя серверная запись/бронирование — когда нужны оплата, управление слотами, БД, аналитика.
