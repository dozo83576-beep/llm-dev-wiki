# Legacy design runtime integration

Ранее этот документ закреплял конкретный дизайн-инструмент и отдельный fallback за определёнными runtime. Это больше не часть канонического pipeline: доступность и интерфейсы инструментов меняются быстрее вики.

Текущее правило:

- модель нативно формирует design direction и реализацию;
- внешний дизайн-инструмент выбирается только по фактической доступности и необходимости получить или изменить внешний артефакт;
- отсутствие конкретного инструмента не блокирует нативную работу;
- внешняя write/publish операция требует явного approval;
- перед облачной передачей данные обезличиваются с учётом 152-ФЗ.

Актуальный канон: [External design skills and tools](External-design-skills.md) и [Model capability boundaries](Model-capability-boundaries.md). Исторические команды намеренно удалены, чтобы не выдавать runtime-специфичный интерфейс за стабильный контракт.

## Когда использовать

Только для разбора старой ссылки или миграции исторического проекта на capability-policy.

## Когда не использовать

Не используй как инструкцию для новой design-задачи: документ архивный.

## Правила

Название runtime не определяет владельца design-capability; действуют project brief, manifest и фактическая доступность инструмента.

## Частые ошибки

Восстанавливать удалённые CLI-команды, считать отсутствие одного дизайн-инструмента блокером или передавать в облако необезличенные данные.

## Проверка

Ссылки должны вести только на текущий capability-policy и активные документы; semantic verifier не должен находить устаревшие runtime-маркеры.
