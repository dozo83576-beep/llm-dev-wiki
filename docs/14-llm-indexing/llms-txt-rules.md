# llms.txt rules

`llms.txt` — это короткая карта вики/сайта, оптимизированная для LLM-агентов. Не дамп всего контента, а навигационный документ, по которому LLM понимает, что есть в корпусе и как им пользоваться.

## Когда использовать

- Любой публичный или внутренний сайт с документацией, который LLM-агенты должны корректно понимать.
- Корпус, который индексируется в RAG / File Search — `llms.txt` служит manifest'ом для индексера.

## Когда не использовать

- Сайт без структурированной документации — нечего описать.
- Закрытый корпус, где LLM не должны иметь доступа — не публикуй `llms.txt`.

## Что должно быть

- **Назначение вики**: 1–2 предложения о том, что это и для кого.
- **Source policy**: что внутри (конспекты, ссылки, дата проверки), что снаружи (полные тексты книг/курсов).
- **Ключевые входные документы**: overview, document-standard, full-cycle, stack-selection, playbooks index.
- **Playbooks** / типы проектов с короткими описаниями.
- **Prompts** — основной набор инженерных промптов.
- **Security rules**: что недопустимо хранить (секреты, PII), как обращаться с MCP write-tools.
- **Запреты**: ясно перечислить, чего LLM не должен делать на основании этого корпуса.

## Производственные паттерны

- Короткий (≤ 300 строк) и плоский: список ссылок, а не структура дерева.
- Ссылки относительные от корня сайта/репо.
- Без боковых тем (changelog, contributors) — для них есть другие файлы.
- Обновлять при изменении основных входных документов.

## Частые ошибки

- Дублировать в `llms.txt` весь контент — теряется смысл "карты".
- Забыть запреты — LLM считает, что любые данные годятся.
- Не обновлять при изменении структуры разделов — ссылки ломаются.

## CI-проверка

- Все ссылки из `llms.txt` валидны.
- Файл умещается в разумный токен-budget (≤ ~3000 токенов).
- Изменение `llms.txt` ревьюится как код, а не как побочный эффект.
