# Internationalization

i18n нужен, когда продукт поддерживает несколько языков, регионов, валют, дат и форматов. Это архитектурное решение, а не финальная замена строк.

## Production-паттерны

- Locale в URL или явной настройке пользователя.
- Все пользовательские строки проходят через translation layer.
- Даты, числа и валюты форматируются через Intl.
- Layout проверяется на длинных строках.

## Частые ошибки

- Hardcoded strings в компонентах.
- Перевод только текста без форматов дат/валют.
- UI ломается на длинных немецких/русских строках.
