# Internationalization

i18n нужен, когда продукт поддерживает несколько языков, регионов, валют, дат и форматов. Это архитектурное решение, а не финальная замена строк.

## Production-паттерны

- Locale в URL или явной настройке пользователя.
- Все пользовательские строки проходят через translation layer.
- Даты, числа и валюты форматируются через Intl.
- Layout проверяется на длинных строках.

## Частые ошибки

- Hardcoded strings в компонентах.
- Перевод только текста без форматов дат/валют.
- UI ломается на длинных немецких/русских строках.

## Когда использовать

Используй i18n, если продукт реально поддерживает несколько рынков, языков, валют, часовых поясов или юридических регионов.

## Когда не использовать

Не добавляй i18n-инфраструктуру в одноязычный MVP без подтвержденной потребности: она увеличивает стоимость UI, контента и QA.

## Проверка

Проверь длинные строки, plural rules, даты, валюты, RTL при необходимости, SEO hreflang для публичных страниц и fallback при отсутствующем переводе.

Источник: [MDN Intl](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl).
