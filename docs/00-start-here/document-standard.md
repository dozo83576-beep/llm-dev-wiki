# Стандарт production-документа

Документ в этой вики должен быть полезен для принятия инженерного решения, а не просто пересказывать документацию.

## Обязательная структура

1. Назначение: какую проблему решает технология, паттерн или процесс.
2. Когда использовать: условия, при которых выбор оправдан.
3. Когда не использовать: признаки, что решение будет лишним или рискованным.
4. Production-паттерны: практики, которые можно повторять в проектах.
5. Частые ошибки: реальные способы сломать качество, безопасность или сроки.
6. Security/performance risks: что проверять до релиза.
7. Testing strategy: какие тесты доказывают корректность.
8. Edge cases: ситуации, которые часто забывают.
9. Источники: официальная документация и вторичные материалы с пометкой.

## Политика источников

Вики не копирует книги, статьи, курсы и документацию целиком. Допустимо хранить собственный краткий конспект, практическую инструкцию, ссылку на источник, дату проверки и лицензионную пометку для open-source материалов.

## Definition of Done

- Есть front matter.
- Есть практическое решение или чеклист.
- Есть хотя бы один источник для внешнего утверждения.
- Нет незавершенных маркеров.
- Можно применить документ в проекте без дополнительного объяснения автора.
