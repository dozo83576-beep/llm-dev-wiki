# Site handoff template

Шаблон фиксирует передачу сайта заказчику после production-деплоя. Используй его для лендингов, сайтов с CMS, интернет-магазинов и web-приложений.

Секреты, пароли, токены, cookies, приватные ключи и персональные данные в `handoff.md` не записываются. Для доступов фиксируется только сервис, владелец, способ передачи и ссылка на безопасное хранилище без раскрытия значения секрета.

## Когда использовать

- Сайт уже развернут на production-домене.
- Нужно передать заказчику ссылки, инструкции, зоны ответственности и условия поддержки.
- Нужно зафиксировать версию релиза, чтобы отделять баги от новых задач.

## Когда не использовать

- До production-деплоя: сначала пройти release flow и smoke-проверки.
- Для передачи секретов: используй password manager или штатное приглашение в сервис.

## Последовательность после деплоя

1. Открыть production URL и пройти smoke-проверку.
2. Проверить формы, заявки, письма, мобильную версию, HTTPS и основные страницы.
3. Зафиксировать commit, branch, tag или номер релиза.
4. Сгенерировать `handoff.md` командой `tools/new-handoff.ps1`.
5. Заполнить недостающие ссылки на админку, аналитику, DNS, CMS и безопасные хранилища доступов.
6. Отправить заказчику production-ссылку, чеклист проверки и текст приемки.
7. Исправить баги по согласованному ТЗ, новые функции вынести в отдельную оценку.
8. Получить письменное подтверждение приемки.

## Команда генерации

```powershell
pwsh D:\Work\llm-dev-wiki\tools\new-handoff.ps1 `
  -ProjectRoot D:\Work\auto-service-website `
  -ProjectName "Auto Service Website" `
  -ProductionUrl "https://example.com" `
  -SupportDays 14
```

## Шаблон `handoff.md`

```markdown
# Передача проекта: <ProjectName>

## Сводка

| Поле | Значение |
|---|---|
| Production URL | <ProductionUrl> |
| Preview / staging URL | <PreviewUrl> |
| Репозиторий | <RepoUrl> |
| Дата деплоя | <DeployDate> |
| Дата передачи | <HandoffDate> |
| Версия релиза | <ReleaseVersion> |
| Commit | <Commit> |
| Branch | <Branch> |

## Проверка после деплоя

- [ ] Сайт открывается по production-домену.
- [ ] HTTPS работает без предупреждений браузера.
- [ ] Основные страницы открываются без 404/500.
- [ ] Меню, кнопки и внутренние ссылки работают.
- [ ] Формы отправляются.
- [ ] Письма или заявки приходят в согласованный канал.
- [ ] Мобильная версия проверена.
- [ ] Нет тестовых текстов, заглушек и debug-элементов.
- [ ] Нет критичных ошибок в консоли браузера.
- [ ] Страница 404 работает корректно.
- [ ] SEO/analytics подключены, если входили в задачу.

## Доступы

Не записывать пароли, токены, cookies, приватные ключи и секретные значения.

| Зона | Сервис / ссылка | Владелец | Как передано | Статус |
|---|---|---|---|---|
| Хостинг |  |  | Приглашение / password manager | [ ] |
| Домен / DNS |  |  | Приглашение / password manager | [ ] |
| CMS / админка |  |  | Приглашение / password manager | [ ] |
| Репозиторий |  |  | Приглашение в GitHub/GitLab | [ ] |
| Аналитика |  |  | Приглашение | [ ] |
| Почта / формы |  |  | Приглашение / password manager | [ ] |
| CRM / API |  |  | Приглашение / password manager | [ ] |
| Платежи |  |  | Приглашение владельца аккаунта | [ ] |

## Что передано заказчику

- [ ] Ссылка на production-сайт.
- [ ] Инструкция входа в админку, если есть админка.
- [ ] Инструкция изменения контента.
- [ ] Инструкция просмотра заявок.
- [ ] Ссылка на репозиторий или архив исходников.
- [ ] Ссылка на аналитику, если входила в задачу.
- [ ] Условия гарантийной поддержки.

## Сообщение заказчику

Сайт развернут на production:
<ProductionUrl>

Пожалуйста, проверьте одним списком:
1. Основные страницы.
2. Формы заявок.
3. Контакты, тексты и изображения.
4. Мобильную версию.
5. Сценарии покупки, заявки или регистрации, если они есть.

Баги по согласованному ТЗ исправляются в рамках передачи. Новые функции, новые страницы, изменения дизайна и новые интеграции оцениваются отдельно.

## Подтверждение приемки

| Поле | Значение |
|---|---|
| Дата приемки |  |
| Кто принял |  |
| Где подтверждено |  |
| Комментарий |  |

После подтверждения приемки новые функции, новые страницы, изменения дизайна, новые интеграции и изменения бизнес-логики считаются отдельными задачами.

## Поддержка

- Гарантийный срок: <SupportDays> дней.
- В гарантию входят баги по согласованному ТЗ текущего релиза.
- В гарантию не входят новые функции, новые страницы, правки дизайна, новые интеграции, изменение текстов и изменение бизнес-логики.
- Хостинг, домен, платные сервисы и подписки оплачивает заказчик, если не согласовано иначе.
```

## Проверка

- `handoff.md` создан в корне проекта.
- Production URL, дата, commit, branch и tag заполнены.
- Секреты не передаются через файл.
- Заказчик письменно подтвердил приемку.
