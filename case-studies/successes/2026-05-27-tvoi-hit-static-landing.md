# Контекст

Для музыкальной школы "ТВОЙ ХИТ" был подготовлен статический сайт с несколькими HTML-страницами, локальными фотографиями, CTA, блоками направлений, преподавателей, мероприятий, цен, FAQ и контактов.

# Решение

Сайт оставлен как статический HTML/CSS/JS-проект без сборщика: это ускорило локальную проверку, упростило ревью верстки и не добавило инфраструктуру ради лендинга. Для проверки в браузере проект запускался из корня через `python -m http.server --bind 127.0.0.1`, потому что прямой `file://` был заблокирован политикой встроенного браузера.

После визуального ревью была исправлена проблема контраста: чистый белый текст, рассчитанный на темную тему, попадал на светлые секции. В CSS введены отдельные смысловые цвета для текста на темных и светлых поверхностях, а компоненты светлых секций переопределяют наследование явно.

Для заявок использован serverless endpoint `/api/lead`: клиентская форма отвечает за UX-валидацию и состояние отправки, сервер повторно валидирует payload, применяет honeypot, экранирует пользовательский текст и отправляет уведомление в Telegram через Bot API.

# Почему сработало

- Статический стек соответствовал задаче: публичный сайт с маркетинговым контентом, локальными изображениями и минимальной интерактивностью.
- Локальный HTTP-сервер дал поведение ближе к production, чем открытие HTML-файла напрямую.
- Семантические токены `text-on-dark` и `text-on-light` убрали зависимость читаемости от случайного наследования глобального `--text`.
- Проверка computed styles показала фактические цвета выбранных элементов, а не только ожидаемые CSS-значения.
- Telegram-уведомления закрыли MVP-потребность в быстрой обработке заявок без внедрения CRM, но секреты и validation остались на серверной границе.

# Кодовые и архитектурные паттерны

Повторять подходы:

- [Telegram lead notification](../../patterns/backend/telegram-lead-notification.md): держать Telegram Bot Token, server validation и message escaping на backend/serverless endpoint.

# Ограничения

Статический HTML без сборщика подходит для небольшого сайта, но плохо масштабируется при большом количестве повторяющихся компонентов, CMS-контенте, многоязычности или сложной форме заявки. В таких случаях нужен Astro, Next.js static export или CMS-слой.

Telegram как канал заявок подходит для MVP, но не заменяет CRM, хранение consent, retry-механизм и аналитику продаж.

# Проверка

- Открытие через встроенный браузер по `http://127.0.0.1:8000/index.html`.
- Проверка title страницы: "ТВОЙ ХИТ - музыкальная школа в Екатеринбурге".
- Проверка FAQ: вопрос получил `rgb(23, 19, 12)` с contrast ratio `13.92:1`.
- Проверка текста в светлой секции "Как проходит занятие": `rgb(94, 87, 76)` с contrast ratio `5.36:1`.
- Быстрый аудит видимых элементов в светлых секциях не нашел светлый текст на светлом фоне.
- Проверка lead flow по коду: клиент отправляет `fetch('/api/lead')`, endpoint принимает только `POST/OPTIONS`, валидирует телефон и направление, поддерживает dry-run без Telegram env vars вне production.
