# Lesson: дата в генерируемых файлах — UTC и стабильность, иначе ложный stale в CI

## TL;DR

Если генератор пишет в файл «сегодняшнюю» дату локальной машины, а CI сверяет регенерацию через
`git diff --exit-code`, то машина в UTC+N и UTC-runner дадут разные даты для одного и того же
корпуса — и CI упадёт с ложным «file is stale». Дату брать по UTC и не переписывать, если остальное
содержимое не изменилось.

## Контекст

`tools/build-index.ps1` генерирует `docs/INDEX.md` с полем `updated: "<дата>"` во front matter.
`ci-local.ps1` (и GitHub Actions) после регенерации проверяет `git diff --exit-code docs/INDEX.md` —
идемпотентность генерации. Локальная машина в UTC+5, runner — UTC.

## Что произошло

Индекс был закоммичен локально после полуночи местного времени (`updated: "2026-07-05"`). Runner
регенерировал его в 21:37 UTC 2026-07-04 → `updated: "2026-07-04"` → diff в одной строке → шаг
`Build INDEX.md` упал: «docs/INDEX.md is stale» (run 28720393244). Локально при этом всё было зелёно.

## Корень

`(Get-Date -Format "yyyy-MM-dd")` возвращает локальную дату, а «сегодня» в разных часовых поясах —
разные календарные дни несколько часов в сутки. Плюс дата писалась при каждом прогоне, даже когда
содержимое индекса не менялось, — то есть выход генератора зависел от момента запуска, а не только
от входных данных.

## Новое правило

Когда генерируемый файл содержит дату/время и проверяется diff-проверкой → (1) время только UTC;
(2) метка обновляется лишь при фактическом изменении остального содержимого — сгенерируй текст с
плейсхолдером, сравни с существующим файлом при старой дате, и только при отличии подставь новую.
Эталонные реализации: `tools/build-index.ps1` (после fix `48d7f1b`) и `same_manifest`-подход в
`tools/build_embeddings.py` (сохраняет `generated_at` при неизменных стабильных ключах).

## Применимость

Любые генераторы с датой в выводе + staleness-check в CI (индексы, манифесты, отчёты). Не относится
к логам и датированным отчётам, которые не сверяются diff'ом (`technology-update-report.md`).
