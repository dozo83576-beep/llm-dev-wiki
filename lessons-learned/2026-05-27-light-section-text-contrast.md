# Вывод

Если дизайн смешивает темные и светлые секции, нельзя полагаться на один глобальный `--text`. Для текста нужны смысловые токены по поверхности: отдельно для темного и светлого фона.

# Контекст

В статическом лендинге "ТВОЙ ХИТ" основная палитра начиналась как темная, но затем основные секции стали светлыми. Часть элементов, например пункты в FAQ и блоке "Как проходит занятие", продолжила наследовать светлый цвет текста и стала плохо читаться.

# Что произошло

Пользователь отметил белый текст на светлом фоне. Исправление через одну локальную правку решало только выбранный элемент, поэтому была введена системная схема: теплый светлый текст для темных поверхностей, темный основной текст и приглушенный текст для светлых секций.

# Корень

Цвет текста был назван по роли "основной текст", но фактически был привязан к темной поверхности. Когда фон секции изменился, переменная сохранила старый смысл и начала работать против читаемости.

# Новое правило

Когда страница содержит разные типы поверхностей, используй токены вида `text-on-dark`, `text-on-light`, `text-on-light-muted` и проверяй computed color выбранных элементов после визуального ревью.

# Применимость

Правило применимо к лендингам, продуктовым страницам, dashboard-виджетам и компонентам с карточками поверх фото. Оно избыточно для интерфейса с единственной неизменяемой темой и без локальных цветовых контекстов.
