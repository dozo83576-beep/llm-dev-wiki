# Plan-режим обходит оркестратор build-modern-site

## Контекст

Тестовый прогон системы на проекте `local-market-woo` (маркетплейс на WooCommerce). Первое сообщение пользователя содержало триггерную фразу «Я хочу создать сайт …», но сессия Claude Code стартовала в **plan-режиме** — и его встроенный workflow (Explore/Plan-субагенты) перехватил управление. `/build-modern-site` не был вызван ни разу; ни один из `site-*` скиллов не был вызван за весь проект.

## Последствия (аудит «задумано vs выполнено», 17 фаз)

- Полностью пропущены: preflight-скрипты (фазы 0–1), конкурентный анализ (3), **контент (8) — сайт остался без юридических страниц/согласий 152-ФЗ**, **дизайн (9) — anti-slop правила AGENT-PREFERENCES не применены**, **SEO (12)**, **формальное ревью по чеклистам (13)**, **capture-learnings (17)**.
- Выполнены по смыслу, но мимо скиллов: discovery (через ad-hoc вопросы), архитектура (generic Plan-агент), backend/frontend (напрямую).
- Качество кода получилось высоким (субагенты сами читали вики-доки), но воспроизводимость нулевая: следующая сессия может пропустить другие фазы.
- Отдельная находка: уроки в `lessons-learned/` не были подняты перед работой — проблема WP 7.0 на Windows (записанная 2026-06-21) решалась заново.

## Причина

Правило «invoke Skill BEFORE any other response» конкурирует с системным workflow plan-режима, и plan-режим побеждает: его инструкции предписывают конкретную последовательность (Explore → Plan → ExitPlanMode), не упоминая скиллы-оркестраторы. SKILL.md build-modern-site не описывал взаимодействие с plan-режимом.

## Правило

1. Триггер «Я хочу создать сайт…» обязывает войти в `/build-modern-site` **даже в plan-режиме**: фазы 1–7 пайплайна (preflight → discovery → анализ → стек → playbook → AGENTS.md → архитектура) и есть содержимое плана; ExitPlanMode ставится после фазы 7, реализация продолжает пайплайн с фазы 8.
2. Перед стартом любой фазы реализации — grep по `lessons-learned/` на теги стека (wordpress, astro, …), чтобы не решать записанные проблемы заново.
3. Если стадия пропускается осознанно (стек зафиксирован клиентом → сокращённая фаза 4), это фиксируется явно в плане с причиной — молчаливый пропуск недопустим.

## Проверка

- В SKILL.md build-modern-site добавлена секция «Plan-режим Claude Code» (2026-07-02).
- Stop-hook capture-learnings починен: раньше писал подсказку в stderr при exit 0 (невидимо ни модели, ни пользователю в desktop-приложении), теперь возвращает `{"decision":"block","reason":…}` с троттлингом и loop-guard — петля самообучения замыкается.
- Роутер `site-stack-router.ps1` не распознавал «маркетплейс»/«woocommerce» вовсе (confidence low на явном запросе) — добавлены правила `marketplace` и `woocommerce`, включая маршрут для зафиксированного клиентом стека.
